How to Demonstrate CI/CD Pipeline Automation in Real-Time

Step 1

1. Version Update Demo (Green Flow)

Change version in server.js & package.json from v1.0.0 to v1.0.1.

git commit -am "chore: bump version to v1.0.1" && git push

Observe CodePipeline automatically start, build, test, and deploy the new version!

Step 2

2. Failure Test Demo (Red Flow)

Uncomment the intentional failure in tests/test.js or add a broken assertion.

git commit -am "test: intentional test failure" && git push

CodeBuild detects test failure & immediately aborts. Bad code NEVER reaches production!

Step 3

3. Self-Healing & Fix (Recovery)

Fix the test or revert the commit and push again.

git commit -am "fix: restore passing tests" && git push

Pipeline transitions back to SUCCESS and completes deployment seamlessly.

DevOps Viva & Examination Quick Reference

Essential questions and concise answers for B.Tech project viva

Q1: What is CI/CD and why is it important in modern cloud engineering?
CI (Continuous Integration): Automatically building and testing code on every commit to catch bugs early.
CD (Continuous Delivery/Deployment): Automatically packaging and deploying validated code to staging/production with zero manual intervention.
Q2: What is the purpose of buildspec.yml in AWS CodeBuild?
It is a YAML configuration file that defines the commands and environment CodeBuild uses during the build lifecycle across 4 main phases: install, pre_build (unit tests), build (Docker build), and post_build (artifact generation).
Q3: What happens if an automated test fails during AWS CodeBuild?
The pre_build phase exits with a non-zero exit code (code 1). AWS CodeBuild terminates with status FAILED, and AWS CodePipeline immediately stops the pipeline, preventing bad code from ever reaching the live deployment environment.
Q4: Why do we containerize this application with Docker?
Docker packages the application, runtime (Node.js), dependencies, and OS libraries into a lightweight, portable container. This eliminates the classic "it works on my machine" problem, ensuring identical behavior across local developer workstations and AWS production.
Q5: How does AWS CodePipeline know when a developer pushes code to GitHub?
GitHub uses AWS CodeStar Source Connections or Webhooks. When a git push occurs on the main branch, GitHub sends an event payload to AWS CodePipeline, which immediately triggers the automated pipeline execution.
